## 0. 开场与两个问题（0:00–4:00）

【PPT：封面】

各位同学好。我是开放原子开源社团的 ______。去年学长带大家走进开源世界，讲了 Linux、许可证、GitHub。今天这 45 分钟，我换一个更「下手就能练」的题目：**怎么看论文**。

不是教你们写论文，也不是要你们今晚读懂一篇顶会。是教你们一件事：面对一篇十几页、满屏英文和公式的 PDF，**先看什么、看到什么程度可以停、什么时候才值得死磕**。

【PPT：两个问题】

正式开始前，还是先问两个问题。大胆说就行，说错了正好。

第一个：你们觉得论文是不是应该从第一页、第一个词，一路读到最后一页？  
（停 5 秒。大概率有人点头。）

第二个：如果只准你花 10 分钟看一篇论文，你先看哪里？摘要？引言？还是直接翻到实验数字？  
（再停。收集两三个答案，不要评判对错。）

我先把底牌亮出来：**绝大多数论文，都不该被「读完」。** 该被「扫一遍，再决定值不值得读第二遍」。这不是偷懒，是研究人员的常规动作。今天我们把它练会。

手里的样本，是我最近在看的一篇开源项目论文：**MinerU**。上海人工智能实验室做的文档抽取工具。你们以后用大模型、做 RAG、把 PDF 转成 Markdown，很大概率会碰到它，或者它的同类。

## 1. 开源社团为什么要看论文（4:00–8:00）

【PPT：论文是项目的说明书】

有同学可能会想：我是来社团学开源的，又不是来读研的，看论文干什么？

一个开源项目通常有三层皮：

1. **仓库**：代码、Issue、PR，这是「它现在长什么样」。
2. **README / 文档**：这是「你怎么把它跑起来」。
3. **论文**：这是「作者当初为什么这么做、跟谁比过、自己认哪些短板」。

只看 README，你会装软件。看过论文，你才知道这个项目在怕什么、在赌什么。给项目提第一个 Issue 或第一篇文档补丁时，这两种人的问题质量完全不一样。

MinerU 就是现成例子。仓库在 GitHub：`opendatalab/MinerU`。论文在 arXiv：2409.18839。同一拨人，同一件事，两种写法。论文写「为什么现有开源方案不稳定」，仓库写「你今天怎么用」。

再讲一句大一就能用上的话：论文不是教科书。教科书追求完备，论文追求**在一个窄问题上往前拱一小步**。所以你卡住，常常不是因为你笨，是因为它本来就没打算从零教你。

## 2. 五种读法，四种错（8:00–12:00）

【PPT：别这样读】

我见过、也自己干过这些事：

1. **线性精读**：从 Introduction 第一个词啃到 References。两小时后只记得自己很累。
2. **全篇荧光笔画**：颜色很多，脑子里没有结构。
3. **逐句翻译**：每个生词都查，读完一段忘了上一段。
4. **第一组公式劝退**：方法节一出现符号就关 PDF，认定「这不是我能看的」。
5. **把论文当说明书**：期望它像 C 语言教材一样，从环境安装讲到作业题。

这些错有一个共同源头：你把「阅读」理解成「消费完所有文字」。研究人员不是这么干的。他们更像在地图上先标景点，再决定进哪栋楼。

今天只改一个习惯：**先决定深度，再决定页数。**

## 3. 方法总览：最多三遍（12:00–15:00）

【PPT：三遍阅读】

方法来自滑铁卢大学（现在在剑桥）的 S. Keshav，2007 年登在 ACM SIGCOMM 的通讯上，两页纸，被后来几乎所有「如何读论文」课重复引用。

他的原话大意是：不要从头犁到尾，最多读三遍，每一遍目标不同。

- **第一遍**：鸟瞰。5 到 10 分钟。知道这是什么、值不值得继续。
- **第二遍**：抓住内容，不抠细节。大约一小时。能把主线讲给别人。
- **第三遍**：几乎在脑子里重做一遍。一小时到五小时。只有你真的要吃透时才做。

对大一，我再加一条校规：

- 路过的论文：只做第一遍。
- 你感兴趣、下周可能用到的：做第二遍。
- 你要复现、跟代码、写报告、提 PR 的：才做第三遍。

所以「我看不懂」往往不是失败，是**你还没选对遍数**。

## 4. 第一遍 + 现场拆 MinerU（15:00–25:00）

【PPT：第一遍清单】

第一遍只做四件事，其它都假装不存在：

1. 认真读标题、摘要、引言。
2. 只读各节标题，正文跳过。
3. 读结论。
4. 扫一眼参考文献，圈出你听说过的名字。

做完，回答五个 C。我把它译成大一能说出口的中文：

| 英文 | 你问自己的话 |
|------|----------------|
| Category | 这是一篇什么类型的论文？系统、评测、综述，还是理论？ |
| Context | 它站在谁的肩膀上？在跟谁比？ |
| Correctness | 它的前提听起来站得住吗？有没有一眼假的假设？ |
| Contributions | 它自己声称贡献了什么？最多三条。 |
| Clarity | 写得清楚吗？图和标题能不能带路？ |

答得出来，第一遍就毕业。答不出来，多半是你还没按清单走，不是论文太难。

【PPT：MinerU 封面信息】

我们现在不翻细节，现场走一遍。各位跟着我看标题：

*MinerU: An Open-Source Solution for Precise Document Content Extraction.*

开源、精确、文档内容抽取。一件事说完了。作者单位：上海人工智能实验室。

摘要里三句话就够记：

1. 文档种类太多，现有开源方案质量不稳。
2. MinerU 用 PDF-Extract-Kit 的模型，再加细的前处理和后处理。
3. 实验说它在多种文档上都更稳，项目已开源。

【PPT：MinerU 目录当地图】

不要读正文。只看目录：

- 1 Introduction
- 2 Framework：预处理、解析、后处理、格式转换
- 2.2 解析里面有版面、公式检测、公式识别、表格、OCR
- 3 Quality Assessment
- 4 Conclusion

光看标题，你已经知道：这不是一篇「提出一个新损失函数」的论文，这是一篇**把流水线搭起来、再证明它在杂文档上更好用**的系统论文。

结论段也只抓一句：高质量模型推理 + 细的前后处理，让多样文档也能抽出能用的结果。后面的未来工作（组件、速度、benchmark）听过即可。

【PPT：MinerU 的五个 C】

我把五个 C 写成可以抄的答案。你们可以用手机拍下来，但更有用的是自己改写成一句话。

1. **类型**：系统 / 工具论文。多模块文档解析，不是纯理论，也不是大模型聊天。
2. **语境**：大模型训练和 RAG 需要干净的文档数据。前人有四条路——整页 OCR、PDF 库硬解析、多模块流水线、端到端多模态。MinerU 选第三条，并强调「多样真实文档」而不只是论文 PDF。
3. **前提**：如果版面、公式、表格都能先被找准，再配上阅读顺序和去噪，最后的 Markdown 就会比「一股脑 OCR」干净。这个前提合理，但是否真好，要等第二遍看图和表。
4. **贡献**：开源一站式抽取；能覆盖教材、试卷、研报等杂版面；能丢掉页眉页脚；能处理跨栏跨页；公式和表格单独识别。
5. **清楚吗**：结构清楚，图很多，适合当第一篇样本。英文也不绕。

到这里停。问现场：

「如果这不是你的方向，第一遍到此结束，完全合法。有没有人现在就能用自己的话，用三十秒介绍 MinerU？」  
（点 1–2 个同学。引导他们说：问题是 PDF 太杂，方法是拆模块再拼接，结果是开源工具。）

第一遍的成果不是「我读懂了」，是「我知道它大概是什么，以及我要不要继续」。

## 5. 第二遍：图比文字诚实（25:00–35:00）

【PPT：第二遍看什么】

第二遍 Keshav 给了两个硬要求：

- 仔细看图、表、坐标轴。轴有没有标？有没有误差范围？这些能把凑数的工作和扎实的工作分开。
- 先忽略证明和公式展开。把没读过、但反复出现的参考文献标出来，回头当背景。

结束后，你应该能对室友讲：它做了什么、凭什么这么说。讲不出来，就还在第一遍。

MinerU 我只带三张「证据」，不带公式。

【PPT：图 1 流水线】

图 1 是全文最重要的一张。它说 MinerU 不是一个神秘大模型，而是四段：

1. **预处理**：这是不是 PDF？加密吗？扫描件还是可复制文本？中文还是英文？
2. **内容解析**：先找版面，再分别做公式、表格、OCR。
3. **后处理**：去重叠框、删页眉页脚、按人的阅读顺序拼接。
4. **格式转换**：中间 JSON，再导出 Markdown。

请大家记住一个类比：这不是「一个超人把整页吃下去再吐出字」，这是「分诊台 + 专科医生 + 编辑部」。

为什么必须分诊？因为整页 OCR 会把图、表、公式全当成字，噪声极大；用 PyMuPDF 直接抽文本，公式和表格又会烂掉。

【PPT：图 3 双栏惨案】

图 3 是我最想让新生记住的一张。左边：不做版面，OCR 把双栏报纸读成一栏，句子从左栏窜到右栏。右边：先框出栏，再识别，顺序就对了。

这张图在教你两件事：

- 论文的「方法」常常藏在图里，不藏在形容词里。
- 你以后用任何文档工具，都可以问一句：它有没有先理解版面？

【PPT：表 3 数字只看一行】

表 3 比较版面检测。不要读满表。只看一行对比：

- 在论文验证集上，他们微调后的 LayoutLMv3，mAP 是 77.6；一个常见开源基线 DocXchain 是 52.8。
- 教材验证集上，77.6 对不上，是 67.9 对 34.9。教材比论文更难，但他们仍然高一截。

第二遍要养成的习惯：数字出现时，先问三个问题——跟谁比？在什么数据上比？好了多少？答得出来，你就没有被「SOTA」三个字母唬住。

【PPT：第二遍结束标准】

现在请邻座互相说 40 秒：

「MinerU 要解决的是 ______；它不靠一个端到端模型，而靠 ______；我之所以相信它，是因为 ______。」

参考填空：杂文档抽取不稳；版面 + 专科识别 + 后处理；图 3 说明阅读顺序、表 3 说明版面检测确实更好。

能说出来，第二遍对这篇论文就够了。公式识别叫 UniMERNet、表格叫 TableMaster，名字知道即可，不必展开。

## 6. 第三遍：什么时候才值得（35:00–38:00）

【PPT：第三遍很少用】

第三遍 Keshav 写得很狠：假装自己是作者，在脑子里把工作重做一遍。找隐含假设，找没引的相关工作，找实验里不公平的地方。新手可能要四五个小时。

大一什么时候才需要这样？

- 你要复现它，或者课程大作业就做这个。
- 你要给这个仓库提一个认真的 PR。
- 你要写一篇「我读了 MinerU」的读书报告，而且老师要方法细节。

其它时候，停在第二遍是成熟，不是敷衍。

一个加分动作：同一项目常常有续篇。MinerU 2.5 把多模块换成 1.2B 的视觉语言模型，先看缩略图找版面，再在原图像块上认字。你不需要今天读 2.5。你只需要知道：**读懂一篇，下一篇会便宜很多**，因为问题还是那个问题。

## 7. 怎么找到下一篇（38:00–42:00）

【PPT：找论文的四条路】

方法会了，还得知道论文从哪来。开源社团语境里，我只推荐四条路：

1. **从项目回论文。** 打开 GitHub，README 或 About 里经常挂着 Paper / arXiv。MinerU 就是这样。
2. **从论文回项目。** 摘要最后一句、脚注、项目主页，常有仓库链接。能跑的论文，优先读。
3. **从一篇到一片。** 第一遍之后读 Related Work。里面出现的综述（survey）是上天送的地图。再看哪些名字被反复引用，那些人多半是这个方向的地标。
4. **从搜索引擎入场。** Google Scholar 或 arXiv 搜 `document parsing PDF Markdown`，先对最近 3–5 篇做第一遍，不要一上来下载 30 篇。

Keshav 写文献调研时，就是这个顺序。大一不必做综述，但「先三五篇，再下潜」能省掉很多自我感动的忙碌。

和开源怎么接上：

- 看 Issue 前先做第一遍，你问得出「这是版面问题还是 OCR 问题」。
- 写文档补丁时，你能用论文里的词，而不是「这个软件好像挺准」。
- 你也可以只做翻译、整理 FAQ、补一个中文复现笔记。这些都是贡献。

## 8. 带走三件事、社团、提问（42:00–45:00）

【PPT：带走三件事】

如果今天只记住三句，记这三句：

1. **不要线性读完。** 先选深度，再选页数。
2. **第一遍只要 10 分钟和五个 C。** 大多数论文到这里就可以毕业。
3. **图和表比形容词诚实。** 方法在图 1，问题在图 3，成绩在表 3。

【PPT：课后 10 分钟作业】

作业不交，但建议今晚做：任选一篇论文——专业课老师发的、GitHub 上挂着的、或者还是 MinerU——用手机计时 10 分钟，只写五个 C，发给社团群也行。写得丑没关系，写不出来说明你还在读正文，回到清单。

【PPT：社团】

开放原子开源社团不是只给「已经会写代码」的人准备的。看论文、翻译文档、整理常见问题、把今天这套方法教给下一个新生，都算参与。你们要是愿意，下次活动可以带自己的五个 C 来，我们一起挑一篇拆。

【PPT：结束页】

我的问题先到这里。轮到你们：  
现在对「论文」最不舒服的一点是什么？是英文，是公式，还是不知道从哪找？  
（留 1–2 个问题。回答时回到三遍，不要新开话题。）

谢谢。

## 备用 90 秒（超时或冷场）

超时：删掉第 7 段里的第 3、4 条，只留「从仓库回论文」。  
冷场：把摘要投到屏幕上，带全班齐读标题和摘要第一句，再集体填 Category。  
被问「英文太差怎么办」：第一遍允许中译标题和摘要，但五个 C 必须自己写中文，不能复制翻译软件的长句。  
被问「一定要读英文原文吗」：第二遍起尽量看图和原表，翻译可以辅助，不能替代坐标轴。  
被问「和 ChatGPT 的关系」：可以让它解释术语，但五个 C 和「我相不相信这张图」必须自己完成，否则你只是在阅读一篇更流畅的幻觉。
